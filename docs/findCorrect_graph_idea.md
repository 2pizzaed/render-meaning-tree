**Цель:** По уже построенной части трассы найти следующее корректное действие. Граф достраивает прозрачные действия, раскрывает вложенные конструкции и учитывает значения условий, прерывания и эффекты переходов.

Реализация: [findCorrect.tpg](../domain/findCorrect.tpg). Схема: [findCorrect-tpg.drawio](diagrams/findCorrect-tpg.drawio). Граф проверки выбранного действия использует этот поиск для [достраивания прозрачных действий перед проверкой](check_graph_idea.md#алгоритм-в-domainmaintpg). Обозначения определены ниже и используются в декомпозиции и алгоритме.

## Термины и исходные данные

**Конструкция** — часть программы, содержащая действия и правила их выполнения. Правила и объекты ситуации описаны в [domain.md](domain.md). Общие понятия прозрачности, раскрытия и кадров совпадают с [описанием проверок](check_graph_idea.md#термины-и-исходные-данные).

Вход графа: `tpg CtrlFlow_findCorrect(S: TraceState, P: TraceAct)`.

| Обозначение | Смысл и соответствие коду |
| --- | --- |
| $S$ | Состояние трассировки (`TraceState`), включая режим прерывания `S.interruption_mode`. |
| $P$ | Акт последнего корректного действия исходной трассы (`TraceAct`). В обычном режиме найденный шаг становится новым $P$. |
| $L$ | Рабочий акт — точка, от которой ищется продолжение (`TraceAct`). Вначале $L=P$; при достраивании и возврате из функции $L$ меняется. |
| $a_L$ | Конкретное действие рабочего акта: `L->hasAction`. Это сокращение для описания, отдельной переменной `a_L` в графе нет. |
| $T$ | Выбранный переход из правила $a_L$ (`TransitionSpec`). |
| $N$, $N_{absent}$ | Конкретное действие по основной цели $T$ и по запасной цели; в коде `N` и `N_absent`. |
| $N_1$ | Следующее ещё не выполненное действие цепочки при обработке повтора; в коде `N1`. |
| $C$ | Конструкция, раскрываемая из $a_L$ или $N$ (`ConcreteConstruct`). Конструкция самого $a_L$ обозначается явно как `L->hasAction->belongsTo`: она может отличаться от $C$. |
| $A$ | Локальное действие BEGIN раскрываемой $C$. Здесь $A$ не является входным выбором студента, как в графе проверки. |
| $U$ | Отложенное действие, восстановленное по `unfoldedFrom` акта BEGIN. |

- **Прозрачное действие** — шаг, который достраивается автоматически. Непрозрачное действие обычно требует выбора студента; исключение — автоматическое раскрытие конструкции с прозрачным входом.
- **Вход BEGIN и завершение END** — действия, отмечающие начало и конец выполнения конструкции.
- **Раскрытие конструкции до инициировавшего её действия** — порядок, при котором сначала выполняется раскрытая конструкция, а затем само действие.
- **Отложенное действие $U$** — действие, инициировавшее такое раскрытие. Его очередь наступает после END конструкции.
- **Кадр вызова** — привязка актов трассы к одному вызову функции через `inFrame`; вне функций используется кадр программы. При рекурсии кадры различают несколько одновременных вызовов одной функции.

Для поиска нужны частичная трасса и $S$. Акт хранит действие, его значение и использованный переход, если он был. При раскрытии из $N$ акт BEGIN сохраняет `unfoldedFrom = N`; если $N$ отложено, он сохраняет также переход $T$ для последующего добавления $U$. Правила конструкций определяют допустимые переходы, ограничения и эффекты.

## Выходные данные

- Обновлённая трасса: автоматически добавленные действия, входы в конструкции и завершения, включая выходы по прерыванию.
- Обновлённое состояние трассировки $S$.
- В обычном режиме — следующий шаг студента, добавленный в трассу, либо признак завершения программы.
- В режиме достраивания прозрачных действий — трасса, продолженная до границы следующего шага студента; сам этот шаг ещё не добавлен.
- При невозможности продолжить поиск — внутреннее исключение.

В обычном режиме найденный шаг становится новым $P$; состояние $S$ сохраняет применённые эффекты. При достраивании прозрачных действий вызывающий граф определяет текущую точку заново по последнему акту трассы.

## Граничные ситуации для поиска

1. **Программа завершена.** Следующего действия нет; поиск завершается успешно.
2. **Действует прерывание.** Нужно выйти из вложенных конструкций до места, где соответствующий эффект остановит прерывание, либо до корня программы.
3. **Вызов или возврат из функции.** Нужно перейти в новый кадр либо восстановить точку продолжения в кадре вызывающего.
4. **Основная цель перехода недоступна.** Нужно проверить запасные цели в заданном порядке.
5. **Действие уже выполнялось.** Нужно различить следующее действие в цепочке и повтор текущего.
6. **Завершилась конструкция, раскрытая до инициировавшего её действия.** Настала очередь отложенного действия.
7. **Не хватает значений времени выполнения или поиск неоднозначен.** Продолжить рассуждение по имеющимся данным нельзя.

## Декомпозиция переиспользуемых процедур (lambda / fragment)

Нумерация этого списка независима от шагов алгоритма. Верхний пункт задаёт общую задачу; вложенные пункты поясняют назначение каждой процедуры. В скобках приведены имена и типы параметров из `findCorrect.tpg`. $X$ ниже — произвольное конкретное действие, $E$ — эффект.

1. Применить $E$ к $S$: включить новый режим прерывания либо снять текущий, если $E$ останавливает именно его или любое прерывание. (`lambda applyInterruptionMode(E: EffectDeclaration, S: TraceState)`).

2. Найти ближайшее неиспользованное значение времени выполнения действия $X$. (`lambda findUnusedValue(A: ConcreteAction)`).

3. Выбрать правило первой присутствующей запасной цели $T$ в конструкции $C$ с сохранением порядка цепочки. Если цепочки нет, вернуть основную цель $T$. (`lambda toWhenAbsent(T: TransitionSpec, C: ConcreteConstruct)`).

4. Найти точку продолжения $L$: добавить отложенное прозрачное $U$, обработать прерывание $S$, подняться из завершённой конструкции или войти в тело функции. Параметр `last` — рабочий акт $L$, а не обязательно хронологически последний акт трассы. (`fragment findLastTracedAction(last: TraceAct)`).

5. Подготовить вход в $C$: определить кадр нового акта BEGIN и найти само действие входа.

    - Назначить новому BEGIN кадр: после акта вызова с эффектом `add_frame` открыть новый кадр, иначе сохранить кадр предыдущего акта (`lambda frameAfter(prev: TraceAct)`).
    - Найти конкретное действие BEGIN конструкции $C$. Помощник объявлен, но в текущем графе не вызывается: вход ищется непосредственно в местах добавления акта (`lambda beginActionOf(C: ConcreteConstruct)`).

6. Раскрыть $C$, которую инициирует $N$: добавить $N$ и её вход $A$ в установленном порядке. При раскрытии до $N$ сначала добавить только $A$, сохранив $N$ и $T$ в его акте. (`fragment unfoldNewConstruct(C: ConcreteConstruct)`).

7. Обработать отложенное $U$ после END: восстановить его по акту BEGIN, определить, является ли оно шагом студента, и добавить его либо остановиться перед ним.

    - Найти последний BEGIN конструкции акта $L$ в том же кадре, хранящий `unfoldedFrom`; по нему восстанавливаются $U$ и переход к нему (`lambda unfoldBeginAct(t: TraceAct)`).
    - Проверить, наступила ли очередь отложенного действия: $L$ — последний акт трассы, это END конструкции, раскрываемой до действия, и её BEGIN хранит `unfoldedFrom` (`lambda hasPendingUnfold(t: TraceAct)`).
    - Проверить непрозрачность $U$, чтобы отличить шаг студента от автоматически добавляемого действия; прозрачность BEGIN здесь не определяет остановку (`lambda pendingUnfoldIsStep(t: TraceAct)`).
    - Добавить акт $U$, восстановить его кадр и переход из BEGIN, использовать очередное значение, применить эффекты и обновить $L$ (`fragment appendPendingUnfold()`).

8. Выбрать способ обработки $N$: добавить прозрачный шаг, остановиться на шаге студента либо раскрыть $C$. (`fragment classifyAction(N: ConcreteAction)`).

9. Обработать повтор $N$ в кадре $L$: найти ещё не выполненное $N_1$ после $N$ в той же цепочке либо снова классифицировать $N$. Поиск не требует того же `derivedFrom`, что у $N$. Текущее условие требует, чтобы $N_1$ было ближе к $N$, чем последнее действие цепочки; отдельного отбора ближайшего кандидата нет. (`fragment checkRepeatedAction(N: ConcreteAction)`).

10. Отобрать переходы из $a_L$: проверить исходное правило и конструкцию, значение условия, затем приоритет режима прерывания $S$.

    - Отобрать переходы из правила $a_L$ в правиле его конструкции (`lambda transitionFrom(t: TransitionSpec, L: TraceAct)`).
    - Проверить ограничение по условию: если $L$ имеет значение, сравнить ближайшее неиспользованное значение $a_L$ с требуемым переходом значением (`lambda valueFits(t: TransitionSpec, L: TraceAct)`).
    - Выделить переходы с точным ограничением на текущий режим $S$, исключая `any`; они проверяются первыми (`lambda interruptionSpecific(t: TransitionSpec, S: TraceState)`).
    - Отобрать переходы, допускающие режим $S$, включая `any` и отсутствие ограничений; они проверяются, если первый поиск не дал однозначного результата (`lambda interruptionAllowed(t: TransitionSpec, S: TraceState)`).

## Алгоритм (в `domain/findCorrect.tpg`)

1. **Установить $L=P$.** Начать поиск от последнего корректного акта исходной трассы.
2. **Повторять поиск до следующего шага студента.** На каждой итерации выполнять проверки и действия ниже.

    2.1. **Проверить завершение программы.** Если $a_L$ — END корневой конструкции, установить $P=L$ и закончить поиск успешно.

    2.2. **Проверить очередь отложенного действия.** Если $L$ — последний акт трассы и это END конструкции, раскрытой до непрозрачного $U$, то $U$ — следующий шаг студента. В обычном режиме добавить акт $U$ и установить $P=L$; при достраивании прозрачных действий остановиться перед $U$.

    2.3. **Проверить вход в ещё не раскрытую конструкцию.** Если $a_L$ инициирует раскрытие $C$ после себя, BEGIN этой $C$ непрозрачен и в кадре $L$ нет незавершённого входа в $C$, то её вход $A$ — следующий шаг студента. В обычном режиме добавить акт $A$, применить его эффекты и обновить $P$ и $L$; при достраивании остановиться перед $A$.

    2.4. **Найти точку продолжения.** Вызвать `findLastTracedAction(L)`. Сначала добавить отложенные прозрачные $U$. Затем обработать прерывание $S$, добавляя вынужденные END. Конструкция считается незавершённой, если в её кадре нет END в рассматриваемом акте или после него; END прошлого выполнения той же конструкции (предыдущая итерация цикла) её не закрывает. После END перенести $L$ на последний акт, чья конструкция ещё не завершена в его кадре; после перехода с эффектом вызова добавить BEGIN тела функции и сделать его новым $L$.

    2.5. **Выбрать $T$ из правила $a_L$ в его конструкции.** Ограничение по значению условия отбирает допустимые переходы. Сначала искать переход, заданный именно для текущего режима прерывания; если однозначного результата нет, искать среди переходов, допускающих этот режим, в том числе без ограничений или для любого прерывания. Если оба поиска не дали однозначного $T$, вернуть внутреннее исключение `AmbiguousOrMissingTransition`.

    2.6. **Найти $N$ по основной цели $T$.** В конструкции $a_L$ выбрать конкретное действие правила `T->to_`, отличное от $a_L$. Если у $a_L$ есть следующее действие в цепочке, выбрать ближайшее подходящее после него. Возврат назад допускается, если подходящих действий впереди нет и у $T$ не задана цепочка запасных целей.

    2.7. **Проверить запасную цель.** Если $N$ не найдено, выбрать первую присутствующую запасную цель $T$ и действие $N_{absent}$ в конструкции $a_L$. Если у $a_L$ есть следующее действие в цепочке, $N_{absent}$ должно быть ближайшим подходящим после $a_L$. Если и $N_{absent}$ не найдено, вернуть внутреннее исключение `NoNextAction`. Дальнейшие шаги применить к найденному $N$ или $N_{absent}$.

    2.8. **Обработать уже выполненное действие.** Если найденное $N$ встречалось в кадре $L$, найти ещё не выполненное $N_1$ после него по условию п. 9 декомпозиции; совпадение правил $N_1$ и $N$ не требуется. Если $N_1$ нет, снова классифицировать $N$. Для запасной цели проверка устроена так же.

    2.9. **Добавить действие или раскрыть конструкцию.** Классифицировать $N$ (либо заменившее его $N_{absent}$ или $N_1$). Прозрачный шаг добавить, обновить $L$ и продолжить поиск. Шаг студента в обычном режиме добавить как новый $P$, а при достраивании остановиться перед ним. Если $N$ раскрывает $C$, учитывать порядок раскрытия и прозрачность её BEGIN — действия $A$. При добавлении акта использовать очередное значение времени выполнения, учесть эффекты действия и $T$ в состоянии $S$.

3. **Вернуть результат.** В обычном режиме $P$ указывает на найденный шаг студента или завершение программы. При достраивании успешный результат означает достижение границы следующего шага; актуальную точку вызывающий граф восстанавливает по трассе, поскольку $P$ обновляется не на каждом автоматическом шаге.

## Особенности реализации

### Два режима поиска

В обычном режиме граф строит трассу до следующего шага студента включительно. В режиме достраивания он добавляет автоматические шаги и останавливается перед следующим шагом студента. Этот режим используется при проверке ответа.

Непрозрачность сама по себе не всегда означает остановку. Если действие раскрывает после себя конструкцию с прозрачным входом, граф автоматически добавляет действие вместе с этим входом и продолжает поиск. Для отложенного действия возможность остановки определяется прозрачностью самого действия: вход раскрытой конструкции уже выполнен и не заменяет его.

### Раскрытие конструкции до или после инициировавшего её действия

При раскрытии после действия сначала добавляется само действие. Если вход в конструкцию прозрачный, он добавляется сразу и поиск продолжается внутри. Если вход непрозрачный, он обрабатывается как отдельный шаг студента; прозрачное инициировавшее действие проходится автоматически.

При раскрытии до действия порядок такой: вход → внутренние действия → завершение → инициировавшее действие. Сначала добавляется только вход. Его акт сохраняет инициировавшее действие и переход к нему; само действие $U$ добавляется после END с восстановлением $T$ из акта BEGIN.

Прозрачный вход позволяет продолжить поиск внутри конструкции. Непрозрачный вход становится отдельным шагом студента. После завершения раскрытия прозрачное отложенное действие добавляется автоматически, а непрозрачное становится следующим ответом.

Связь между действием и раскрываемой конструкцией определяется общим элементом AST. Саму конструкцию действия исключают из поиска раскрытия: её вход и завершение тоже ссылаются на этот элемент и иначе могли бы раскрыть её повторно.

### Прерывания и точка продолжения

При активном прерывании граф последовательно добавляет завершения незавершённых конструкций, пока не встретит эффект, снимающий этот режим, либо не дойдёт до программы. Если эффект текущего действия останавливает прерывание, выход из его конструкции не добавляется.

Вынужденные завершения добавляются без перехода. Поэтому эффекты правил и конкретных действий применяются явно. Это также позволяет графу проверки отличить автоматический выход по прерыванию от выхода по значению условия.

После завершения конструкции текущая точка поиска переносится на последнее действие, чья конструкция ещё не завершена в его кадре. Она может отличаться от хронологически последнего акта трассы: после возврата из функции последним остаётся завершение её тела, а поиск продолжается от действия вызова.

### Кадры вызовов и рекурсия

Вход в тело функции после перехода с эффектом добавления кадра открывает новый кадр вызова. Остальные акты наследуют кадр текущей точки поиска. Глобальные действия принадлежат корневому кадру.

Входы и завершения конструкции сопоставляются внутри одного кадра. Там же проверяется, выполнялось ли действие ранее. Завершение рекурсивного вызова не закрывает конструкцию вызывающего, а действия внешнего вызова не считаются уже выполненными во внутреннем.

При завершении тела функции точка продолжения возвращается к действию вызова в кадре вызывающего. Правила определения кадров должны совпадать в графе и при сериализации трассы. В [адаптере ситуации](../src/serialization/adapters/situation.py) их восстанавливает `_frame_acts`.

Входы BEGIN исключены из проверки эффекта стека в `findLastTracedAction`: у BEGIN конструкции, раскрываемой до $U$, хранится переход $T$ к отложенному $U$, а не переход к самому входу.

### Значения времени выполнения и повторные входы

При добавлении акта используется ближайшее доступное значение действия, которое затем помечается как использованное. Значения расходуются по всей трассе и не сбрасываются при повторном входе в конструкцию.

Цепочка должна покрывать все выполнения действия. Например, для условия в теле функции, вызванной дважды, нужны значения обоих вызовов подряд. Недостаточная цепочка не позволяет создать очередной акт с требуемым значением и приводит к внутреннему сбою.

При сериализации ситуации признак использования восстанавливается по трассе процедурой `_consumed_value_count_for_action`. Это правило нужно согласованно поддерживать в графе и в Python. Отдельные кадры различают вызовы, но не создают для них отдельных цепочек значений.

### Подготовка правил и ограничения

Поиск использует уже подготовленные правила переходов. Обобщение действий, их эффекты и запасные цели для необязательных частей конструкции должны быть учтены при генерации домена. Порядок запасных целей сохраняется.

Принудительный выход по прерыванию не добавляет отложенное действие конструкции, раскрытой до него. Если такой выход станет возможен, отложенное действие может быть потеряно. В используемых правилах возврат останавливается на границе вызова, а прерывание от самого отложенного действия начинается после завершения его раскрытия. При расширении правил прерываний этот путь нужно проверить отдельно.

### Результаты и ограничения текущего кода

`TraceConfig.stop_on_opaque = true` задаёт обычный режим, `false` — достраивание прозрачных действий. Успешный результат обозначается `conclude: true`; завершение программы дополнительно помечается `skill = "everything_evaluated"`. Внутренние сбои возвращаются через `conclude: error` или `conclude: false` с `exception = true`; у некоторых указан `exceptionName`.

| Внутренний сбой | Идентификатор |
| --- | --- |
| Не найдена незавершённая конструкция для выхода по прерыванию | `UnclosedInterruption` |
| Не найден однозначный допустимый переход | `AmbiguousOrMissingTransition` |
| Не найдено действие ни по основной, ни по запасной цели | `NoNextAction` |

Отбор переходов по условию выполняет `valueFits(T, L)`: если акт $L$ имеет значение, сравнивается ближайшее неиспользованное значение $a_L$ с требуемым $T$ значением. Значение, уже записанное в $L$, при этом не сравнивается. Приоритет среди подходящих переходов определяется режимом прерывания $S$.

В сигнатуре `applyInterruptionMode` этого графа указан тип `EffectDeclaration`, тогда как `main.tpg` и [домен](../domain/domain.loqi) используют `Effect`. Здесь сигнатура воспроизведена по текущему исходнику; это различие типов не исправляется изменением описания алгоритма.
