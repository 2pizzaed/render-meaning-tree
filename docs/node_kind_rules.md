# Правила выбора NodeKind

Ниже систематизировано, как определяется тип узла CFG при построении графа.

## Значения `NodeKind`

- `BEGIN` и `END` — границы составных подграфов.
- `ATOM` — одиночный узел атомарной конструкции.
- `ANY` — вспомогательное значение для запросов/проверок (например, при сопоставлении с пользовательскими действиями).

## Классификация конструкции узла

В процессе построения каждый узел AST анализируется и классифицируется в один из трёх вариантов:

1. **ATOM** — создаётся один узел `NodeKind.ATOM` без вспомогательных границ.
2. **COMPOUND** — создаётся подграф со входом `BEGIN` и выходом `END`.
3. **NONE** — граф для этого действия не строится (noop).

За классификацию отвечает функция `determine_node_construction()` (`src/cfg/node_kind_rules.py`). На вход она получает:

- `action_kind`: KindChain из `ActionSpec.kind`.
- `construct_kind`: KindChain из `ConstructSpec.kind` для соответствующего узла AST.
<del>- `has_function_calls`: признак наличия вызовов функций внутри узла AST.</del>

## Алгоритм

1. Если `construct_kind` содержит `noop`, возвращается `NONE` (граф не строится).
<del>2. Если в узле найдены вызовы функций (`has_function_calls = True`), выбирается `COMPOUND`.</del>
3. Если `action_kind` содержит `compound`, выбирается `COMPOUND`.
4. Если `action_kind` содержит `inline` или `condition`, выбирается `ATOM`.
5. Если `action_kind` содержит `auto`:
   - при `construct_kind` с `compound` → `COMPOUND`;
   - при `construct_kind` с `inline` → `ATOM`;
   - при отсутствии `construct_kind` → `ATOM` (неописанные узлы считаются атомарными).
6. Если `construct_kind` содержит `compound`, выбирается `COMPOUND`.
7. Если `construct_kind` содержит `inline` или `condition`, выбирается `ATOM`.
8. В остальных случаях по умолчанию выбирается `ATOM`.

## Интеграция

- `CFGBuilder.make_cfg_for_construct()` использует классификацию, чтобы понять, создавать ли атомарный узел или составной подграф.
- `CFGBuilder.make_cfg_for_compound()` применяет те же правила при добавлении дочерних узлов: атомарные действия создают `NodeKind.ATOM`, составные — встраиваемые подграфы с `BEGIN/END`, noop-узлы пропускаются.

Таким образом, окончательный `Node.kind` определяется непосредственно при создании узла, согласно правилам выше.
