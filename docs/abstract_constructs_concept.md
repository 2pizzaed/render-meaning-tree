# Абстрактные конструкции для описания задач, условий, ответов и данных тренажера

## Введение

Система абстрактных конструкций представляет собой универсальный механизм описания алгоритмических структур программ независимо от конкретного языка программирования. Эта система лежит в основе тренажера трассировки алгоритмических структур и обеспечивает преобразование исходного кода в интерактивные задачи для студентов.

### Назначение абстрактных конструкций

Абстрактные конструкции служат для:
- **Универсального описания** алгоритмических структур (ветвления, циклы, вызовы функций) независимо от синтаксиса конкретного языка
- **Преобразования** абстрактного синтаксического дерева (AST) в граф потока управления (CFG)
- **Формирования** интерактивных элементов интерфейса тренажера
- **Верификации** ответов студентов через сопоставление с эталонными трассами выполнения

### Связь с графами знаний

Система абстрактных конструкций реализует подход графов знаний для представления структуры программы:
- **CFG как граф знаний** о статической структуре программы
- **Трассы выполнения** как экземпляры динамического поведения
- **Абстрактные конструкции** как онтология предметной области, определяющая правила преобразования и верификации

### Роль в тренажере

Абстрактные конструкции обеспечивают:
1. Автоматическую генерацию задач из реального кода
2. Единообразное представление алгоритмических структур для разных языков
3. Корректную верификацию ответов студентов
4. Расширяемость системы для поддержки новых языков и конструкций

## Концептуальная модель

### Конструкты (ConstructSpec)

**Конструкты** — это универсальные описания алгоритмических структур, которые определяют, как структура из AST должна раскладываться в узлы и дуги CFG.

#### Ключевые характеристики:

- **Языковая независимость**: один конструкт может описывать структуру, общую для нескольких языков (например, `if_statement` в Python и Java)
- **Вариативность**: для одной структуры может быть несколько вариантов конструктов, если поведение отличается в разных языках
- **Декомпозиция**: конструкт состоит из действий (прообразы узлов CFG) и переходов (прообразы дуг CFG)

#### Структура конструкта:

```
Конструкт
├── name: уникальное имя
├── kind: типы конструкции (например, "compound.alternative")
├── ast_node: тип узла AST в нотации Meaning Tree
├── actions: список абстрактных действий
├── transitions: список абстрактных переходов
└── effects: эффекты (опционально)
```

#### Пример:

Конструкт `if_structure` описывает условное ветвление:
- Действия: `first_cond` (первое условие), `if_branch` (ветка при true), `else_branch` (ветка при false)
- Переходы: от BEGIN к условию, от условия к веткам в зависимости от значения, от веток к END

### Абстрактные действия (ActionSpec)

**Абстрактные действия** выражают **роли** в контексте конструкции. Они определяют, какие части алгоритмической структуры должны быть выполнены и в каком порядке.

#### Типы действий:

- **BEGIN/END**: неявные действия для составных конструкций, обозначающие начало и конец структуры
- **Условия** (`condition`): управляющие условия, определяющие дальнейший ход выполнения
- **Блоки** (`block`, `compound`): последовательности инструкций
- **Вызовы** (`call`): вызовы функций и методов
- **Атомарные** (`inline`, `atom`): простые однострочные действия

#### Идентификация действий:

Действия могут описывать, где в AST находится соответствующий узел через:
- `origin`: объект JSON в AST (parent, previous)
- `property_path`: путь к узлу в структуре AST

#### Прозрачность действий:

Действия могут быть:
- **Непрозрачными** (mandatory): требуют явного взаимодействия студента (кнопка в UI)
- **Прозрачными** (none): выполняются автоматически, без необходимости нажатия кнопки

### Абстрактные переходы (TransitionSpec)

**Переходы** связывают действия в последовательность, определяя порядок выполнения алгоритмической структуры.

#### Структура перехода:

- `from_`: от какого действия происходит переход
- `to_`: к какому действию происходит переход
- `to_when_absent`: переход при отсутствии действия `to` в AST (fallback)
- `constraints`: ограничения (значения условий, режимы прерываний)
- `effects`: эффекты (вызовы функций, прерывания)

#### Примеры переходов:

1. **Условный переход**: от условия к ветке в зависимости от значения (`condition_value: true/false`)
2. **Последовательный переход**: от одного элемента последовательности к следующему
3. **Циклический переход**: от конца тела цикла обратно к условию

### CFG (Control Flow Graph)

**CFG** — граф потока управления, построенный на основе конструктов и AST. Представляет статическую структуру программы в виде ориентированного графа с узлами и дугами.

#### Преобразование: Конструкты + AST → CFG

1. Для каждого узла AST находится соответствующий конструкт
2. Конструкт определяет, какие узлы и дуги CFG должны быть созданы
3. Узлы CFG связываются с узлами AST через обёртки (ASTNodeWrapper)
4. Дуги CFG создаются на основе абстрактных переходов

#### Узлы CFG:

- **BEGIN**: начало составного действия
- **END**: завершение составного действия
- **ATOM**: атомарная инструкция

#### Метаданные узлов:

- Связь с AST-узлом (обёртка)
- Связь с абстрактным действием
- Тип отображения (appearance): MANDATORY или NONE
- Эффекты и ограничения

## Использование для описания задач

### Преобразование AST → CFG через конструкты

Процесс построения задачи:

1. **Парсинг кода**: исходный код преобразуется в AST (через Meaning Tree)
2. **Поиск конструктов**: для каждого узла AST находится соответствующий конструкт по типу узла (`ast_node`)
3. **Построение CFG**: конструкт определяет, какие узлы и дуги CFG создавать
4. **Связывание**: узлы CFG связываются с узлами AST через обёртки

#### Пример:

Для кода:
```python
if x > 0:
    print("positive")
else:
    print("non-positive")
```

1. AST содержит узел `if_statement`
2. Находится конструкт `if_structure` для `if_statement`
3. Конструкт создаёт узлы CFG:
   - BEGIN (начало if)
   - ATOM (условие `x > 0`)
   - BEGIN/END (ветка if)
   - BEGIN/END (ветка else)
   - END (конец if)
4. Переходы связывают узлы согласно логике конструкции

### Связь с узлами AST через обёртки

**ASTNodeWrapper** — обёртка над узлом AST, хранящая:
- `ast_id`: уникальный идентификатор узла в AST
- `ast_node`: тип узла в нотации Meaning Tree
- Отношения с родительскими и дочерними узлами

Обёртки обеспечивают:
- Экономию памяти (не хранится полный AST)
- Связь между CFG и исходным кодом
- Корректное отображение кода в UI

### Формирование интерактивных элементов

На основе `appearanceType` действий формируются кнопки в интерфейсе:

- **MANDATORY**: кнопка обязательно отображается и требует нажатия
- **NONE**: кнопка не отображается, действие выполняется автоматически

Прозрачные узлы (NONE) автоматически выбираются при выборе всех непрозрачных узлов до и после них.

## Использование для описания условий

### Управляющие условия как отдельные действия

Условия в алгоритмических структурах (if, while, for) представлены как отдельные действия с типом `condition`.

#### Характеристики условий:

- **Тип**: `inline.condition` или `condition`
- **Роль в конструкции**: например, `cond` в цикле while
- **Идентификация**: путь к узлу условия в AST

#### Пример:

В цикле `while x > 0:`:
- Действие `cond` с типом `inline.condition`
- Идентификация: `property: condition` (узел условия в AST цикла)

### Значения условий в трассах выполнения

**Важно**: В AST и CFG **не хранятся значения** управляющих условий. Значения условий зависят от конкретного выполнения программы и могут быть разными для одного и того же кода.

#### OptionalBoolValue:

Значения условий в трассах представлены как `OptionalBoolValue`:
- `true`: условие истинно
- `false`: условие ложно
- `no_value`: условие отсутствует
- `any`: любое значение

#### Хранение значений:

Значения условий цепляются только к **актам трассы** (TraceAct), а не к узлам CFG. Это позволяет:
- Одному CFG соответствовать множеству трасс с разными значениями условий
- Корректно моделировать различные сценарии выполнения

### Сценарии выполнения (TraceScenarioConfig)

**Сценарии** определяют последовательности значений условий для построения конкретной трассы выполнения.

#### Структура сценария:

- `name`: имя сценария
- `condition_sequences`: словарь {ast_id: [значения]} — последовательности значений для каждого условия
- `max_visits_per_node`: ограничение на количество посещений узла (защита от бесконечных циклов)

#### Пример:

```python
scenario = TraceScenarioConfig(
    name="first_true_then_false",
    condition_sequences={
        42: [True, False]  # Условие с ast_id=42: сначала True, потом False
    }
)
```

## Использование для описания ответов

### Трассы выполнения (TraceAct)

**Трасса выполнения** — это линейная цепочка действий студента, представляющая шаг за шагом выполнение программы.

#### Структура акта трассы:

Каждый акт трассы (TraceAct) содержит:
- `wrapped_ast`: обёртка AST-узла
- `cfg_node`: узел CFG, соответствующий акту
- `action_spec`: спецификация абстрактного действия
- `condition_value`: значение условия (если акт — условие)
- `corresponding_end`: связанный акт конца блока (для BEGIN/END пар)
- `directly_before_of`: следующий акт в трассе (цепочка выполнения)
- `runtime_info`: информация о runtime значениях (аргументы функций, возвращаемые значения)
- `is_known_correct`: флаг корректности акта

#### Линейная структура:

Трасса представляет собой связный список актов через отношение `directly_before_of`, формируя цепочку выполнения от начала до конца программы.

### Связь актов трассы с элементами модели

Каждый акт трассы связан с:
1. **Узлом CFG**: определяет позицию в графе потока управления
2. **Абстрактным действием**: определяет роль в конструкции
3. **Узлом AST**: связь с исходным кодом

Эта тройная связь обеспечивает:
- Верификацию корректности ответа студента
- Сопоставление с эталонной трассой
- Отображение обратной связи с привязкой к коду

### Runtime информация

**RuntimeInfo** содержит данные реального выполнения программы:
- `function_args`: аргументы при вызове функции
- `return_value`: возвращаемое значение функции
- `print_outputs`: вывод через print
- `function_name`: имя функции

Эта информация обогащает трассу данными о реальном выполнении, делая задачу более информативной для студента.

#### Связывание runtime значений:

Runtime значения привязываются к трассе через последовательное связывание:
1. Трасса строится из CFG по сценарию
2. Runtime trace содержит события выполнения (вызовы, возвраты, условия)
3. События последовательно привязываются к соответствующим актам трассы

## Использование для описания данных тренажера

### Метаданные узлов и дуг CFG

**Метаданные** — дополнительная информация, связанная с узлами и дугами CFG:

#### Поля метаданных:

- `is_after_last`: флаг перехода по выходу при отсутствии следующего действия
- `call_count`: количество вызовов функций в атомарном действии
- `hasAbstractAction`: связь с абстрактным действием
- `belongsToASTNode`: связь с узлом AST
- `hasAbstractTransition`: связь с абстрактным переходом

### Эффекты

**Эффекты** — побочные действия, происходящие при прохождении по узлам и дугам CFG:

#### Типы эффектов:

1. **Эффект вызова функции** (`call_stack`):
   - `ADD_FRAME`: вход в тело функции (добавление кадра стека)
   - `DROP_FRAME`: выход из функции (удаление кадра стека)

2. **Эффект прерывания** (`interruption_start/stop`):
   - `break`: прерывание цикла
   - `continue`: прерывание итерации цикла
   - `return`: возврат из функции
   - `exception`: выброс исключения

Эффекты изменяют глобальное состояние решения задачи (режим прерывания, стек вызовов), что учитывается при верификации ответов.

### Ограничения

**Ограничения** уточняют правила переходов:

#### Типы ограничений:

1. **Ограничение значения условий** (`condition_value`):
   - Определяет, при каком значении условия возможен переход
   - Используется для условных переходов (if, while)

2. **Ограничение на режим прерывания** (`interruption_mode`):
   - Определяет, при каком режиме прерывания возможен переход
   - Используется для обработки break, continue, return, exception

### Маршруты (PathInfo)

**Маршруты** — вспомогательная информация о достижимости узлов CFG, используемая для оптимизации рассуждений.

#### Поля маршрута:

- `is_direct`: является ли путь прямым (соседние действия в трассе)
- `ast_actions`: число узлов с непустым AST узлом на пути
- `opaque_actions`: число непрозрачных узлов на пути
- `conditions`: число узлов-условий на пути
- `frames_changes`: число смен кадров стека вызовов
- `frames_added`: число входов в функции
- `frames_dropped`: число выходов из функций

#### Отношения:

- `firstMiddleAction`: первый непрозрачный узел на пути
- `firstMiddleCondition`: первое условие на пути
- `firstMiddleFrameChange`: первый узел со сменой кадра стека

Маршруты используются для:
- Определения корректности шага студента
- Классификации ошибок (слишком рано, слишком поздно, нарушение уровня вложенности)
- Оптимизации поиска пути в CFG

## Абстракция от деталей реализации

### Языково-независимое описание структур

Абстрактные конструкции обеспечивают описание алгоритмических структур без привязки к синтаксису конкретного языка:

- **Один конструкт** может описывать структуру, общую для нескольких языков
- **Вариации конструктов** позволяют учесть различия в поведении между языками
- **Расширяемость**: добавление нового языка требует только определения конструктов для его специфических структур

#### Пример:

Конструкт `if_structure` описывает условное ветвление для Python, Java, C++ и других языков, несмотря на различия в синтаксисе (`if:` vs `if { }`).

### Разделение статической структуры и динамических значений

Система разделяет:

1. **Статическая структура** (CFG):
   - Построена из AST через конструкты
   - Не зависит от значений условий
   - Одна для всех сценариев выполнения

2. **Динамические значения** (трассы):
   - Зависят от значений условий
   - Множество трасс для одного CFG
   - Определяются сценариями выполнения

Это разделение позволяет:
- Эффективно хранить структуру программы
- Генерировать множество задач из одного кода
- Корректно верифицировать различные сценарии выполнения

### Расширяемость через добавление новых конструктов

Система легко расширяется:

1. **Новый язык**: добавить конструкты для специфических структур языка
2. **Новая структура**: определить конструкт с действиями и переходами
3. **Новое поведение**: создать вариацию существующего конструкта

Конструкты определяются в YAML-файле (`constructs.yml`), что делает расширение системы простым и понятным.

## Связь с графами знаний

### CFG как граф знаний о структуре программы

**CFG представляет граф знаний**, где:
- **Узлы** — концепты (действия программы)
- **Дуги** — отношения (переходы между действиями)
- **Метаданные** — свойства концептов и отношений

Этот граф знаний кодирует:
- Структуру программы
- Порядок выполнения
- Зависимости между действиями
- Иерархию вложенности

### Трассы как экземпляры выполнения

**Трассы выполнения** представляют экземпляры выполнения программы:
- Каждая трасса — конкретный путь по графу знаний (CFG)
- Значения условий определяют, какой путь выбирается
- Runtime информация обогащает трассу данными реального выполнения

### Абстрактные конструкции как онтология предметной области

**Абстрактные конструкции** определяют онтологию предметной области:
- **Концепты**: типы алгоритмических структур (ветвления, циклы, вызовы)
- **Отношения**: правила преобразования AST → CFG
- **Ограничения**: правила выполнения (условия, прерывания)
- **Аксиомы**: инварианты системы (например, BEGIN всегда предшествует END)

Эта онтология обеспечивает:
- Семантическую согласованность представления
- Корректность преобразований
- Возможность автоматической верификации

## Ключевые концепции для статьи о графах знаний

### Абстракция

Конструкты описывают структуры **независимо от языка программирования**, обеспечивая универсальное представление алгоритмических знаний. Это позволяет применять единые методы анализа и верификации к программам на разных языках.

### Декомпозиция

Сложные алгоритмические структуры **разбиваются на действия и переходы**, что обеспечивает:
- Модульность описания
- Возможность переиспользования компонентов
- Понятность и поддерживаемость системы

### Связность

Все элементы системы (AST, CFG, трассы) **связаны через общие идентификаторы и отношения**:
- Узлы CFG связаны с узлами AST через обёртки
- Акты трассы связаны с узлами CFG и абстрактными действиями
- Метаданные связывают элементы разных уровней абстракции

Эта связность обеспечивает целостность представления и возможность навигации между уровнями абстракции.

### Расширяемость

Новые языки и структуры **добавляются через новые конструкты** без изменения основной логики системы. Это делает систему гибкой и адаптируемой к новым требованиям.

### Верификация

Трассы проверяются на **соответствие CFG и абстрактным правилам** через:
- Проверку достижимости узлов
- Проверку значений условий
- Проверку режимов прерываний
- Проверку уровня вложенности (стек вызовов)

Это обеспечивает корректную оценку ответов студентов и предоставление содержательной обратной связи.

## Заключение

Система абстрактных конструкций представляет собой мощный механизм для описания алгоритмических структур программ в терминах графов знаний. Она обеспечивает:

- **Универсальность**: описание структур независимо от языка
- **Гибкость**: поддержка различных сценариев выполнения
- **Расширяемость**: простое добавление новых языков и структур
- **Верифицируемость**: автоматическая проверка ответов студентов

Эта система демонстрирует практическое применение графов знаний для решения реальной задачи обучения программированию, обеспечивая автоматическую генерацию задач и интеллектуальную верификацию ответов.
